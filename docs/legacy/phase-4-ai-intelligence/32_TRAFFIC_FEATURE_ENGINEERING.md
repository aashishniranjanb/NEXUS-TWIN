# 32 — Traffic Feature Engineering

## Purpose
Define the exact input features fed to the congestion predictor (`33_CONGESTION_PREDICTION.md`), derived from `TrafficState`/`NetworkState` (`25_TRAFFIC_STATE_MODEL.md`).

## Feature Set (per junction, per prediction timestep)

| Feature | Description | Source |
|---|---|---|
| `vehicle_count` | Current vehicle count at junction | `TrafficState` |
| `density` | Current density (0–100%) | `TrafficState` |
| `average_speed_kmh` | Current mean speed | `TrafficState` |
| `queue_length_m` (per approach, or max across approaches) | Current queue | `TrafficState` |
| `previous_queue_m` | Queue at t-1 (lag feature) | Historical `traffic_state` rows |
| `queue_delta` | `queue_length_m - previous_queue_m` (rate of change) | Derived |
| `waiting_time_s` | Current average waiting time | `TrafficState` |
| `time_of_day` | Encoded (e.g., minutes since simulation start, or sin/cos cyclical encoding) | Simulation clock |
| `signal_phase` | Current phase (one-hot or ordinal encoded) | `TrafficState` |
| `incident_active` | Boolean — is an incident currently affecting this junction/network | `incidents` table |
| `upstream_density` (optional, if time allows) | Density at directly connected upstream junction(s) | `NetworkState`, requires adjacency info from `22_ROAD_NETWORK.md` |

## Lag Window

- Use a short rolling window (e.g., last 5–15 minutes of simulation time) of the above features as model input, consistent with the prediction horizon design in `33_CONGESTION_PREDICTION.md`.
- Aggregate the window into simple statistics (mean, max, trend/slope) rather than feeding a full raw sequence into the Phase-1 model (XGBoost), since tree-based models work better on engineered aggregate features than raw sequences — sequence modeling is deferred to the optional LSTM stretch goal.

## Label / Target

- **Classification framing (simpler, recommended first)**: `will_congest_in_5min` — binary label, e.g., `density_t+5min > congestion_threshold`.
- **Regression framing (if time allows)**: predict `density_t+5min` or `queue_length_t+5min` directly as a continuous value.

## Feature Table Example

```text
junction_id | t | vehicle_count | density | avg_speed | queue_m | queue_delta | waiting_time_s | time_of_day | signal_phase | incident_active | label(t+5min)
A           | 100 | 42 | 58 | 24.1 | 180 | +12 | 8.2 | 0.42 | NS_green | 0 | 1 (will congest)
```

## Data Source for Training
- Generated by running the Reference SUMO simulation (all three control modes, multiple scenarios from `09_USE_CASES.md`) and logging `traffic_state` rows over time — this is the same data used for `43_BASELINE_COMPARISON.md`, reused here as training data (Stage 1/2 of `41_DATASET_PLAN.md`).
- Because we control the simulation, we can generate as much labeled training data as time allows by running repeated randomized scenarios overnight/in parallel with other Phase 4 work.

## Feature Store Note
For the prototype, no formal feature store is needed — features are computed on-the-fly from recent `traffic_state` rows (SQLite query + pandas) at prediction time, matching the "keep it simple" principle from `11_TECH_STACK.md`.

## Dependencies
- Requires `25_TRAFFIC_STATE_MODEL.md` and `28_INCIDENT_ENGINE.md` (for `incident_active`).
- Feeds `33_CONGESTION_PREDICTION.md` directly.
